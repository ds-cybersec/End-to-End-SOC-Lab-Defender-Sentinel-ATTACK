# Credential Access (T1003.001)

Hands-on security investigation and multi-layer telemetry analysis of MITRE ATT&CK T1003.001 (OS Credential Dumping: LSASS Memory). Traced attack execution and defense response across PowerShell command execution, Windows Security detections (HackTool:Win32/DumpLsass.H), Windows Defender XDR alerts, and observed how Windows Defender / PPL successfully intercepted and blocked the unauthorized attempt to dump LSASS memory.  

---

## Test

# Get the Process ID of lsass.exe  
$lsassPID = (Get-Process lsass).Id  

# Execute the memory dump using the native Windows DLL  
rundll32.exe C:\Windows\System32\comsvcs.dll MiniDump $lsassPID C:\temp\lsass.dmp full    

Test execution attempting to invoke the native Windows export function in comsvcs.dll to dump the memory space of lsass.exe to an output file (C:\temp\lsass.dmp), which was intercepted and blocked by the operating system.

One command executed, immediately blocked by security controls. Unlike evasion techniques that destroy logs, credential dumping targets process memory to extract active login tokens or password hashes, but here the defense mechanisms prevented the file creation entirely.

## Why this is T1003.001

MITRE defines T1003.001 as adversaries attempting to dump LSASS memory to extract credential material (passwords, hashes, tickets) from operating system memory.  

### Proof, point by point  

- **PowerShell Execution:** Attempted execution of `rundll32.exe` with `comsvcs.dll` targeting the `lsass.exe` process ID.  
- **Windows Security Detections:** `HackTool:Win32/DumpLsass.H` logged at 2:06 AM and 2:13 AM.  
- **System Block:** `Access is denied` returned by the host environment as PPL / Defender defended the subsystem.  
- **Defender XDR Alert:** Verified prevention event in the Microsoft Defender portal showing the exact command line blocked.

## Stage E: Analysis

Understand the analysis by looking through these 3 points: Response, Why True Positive, and How would a real incident be handled.  

### Response  

The test itself did not require manual remediation to stop the threat because Windows Defender and Protected Process Light (PPL) intercepted and blocked the execution attempt instantly. However, the high-severity heuristic detection registered by the endpoint security sensor triggered automated backend security responses within Microsoft Defender XDR.  

### Why True Positive  
  
- The behavior matched the technique definition for dumping LSASS memory using native Windows DLL exports (`comsvcs.dll` via `rundll32.exe`).  
- The operating system and security controls successfully recognized the malicious pattern and blocked access, returning an `Access is denied` error.   
- Multiple independent monitoring layers—including Windows Security protection history, local PowerShell error codes, and Defender XDR portal alerts—consistently logged the blocked attempt at `2:06 AM` and `2:13 AM`.   
- In this lab it is an intended, simulated action (Atomic Red Team), so the technical classification is a **true positive (blocked threat)** and the business classification is a **benign true positive (authorized security testing)**.  

### How would a real incident be handled  

1. **Triage.** Confirm the alert details: review the Defender XDR alert (`An active 'DumpLsass' hacktool in a command line was prevented from executing`) to identify the impacted device, user account, and exact command string.   
2. **Verify Block Status.** Confirm whether the security controls successfully blocked the action (`Access is denied` / Blocked state) or if memory was successfully compromised.   
3. **Scope the Threat.** Investigate the device timeline preceding and following the alert to determine if the attacker attempted alternative credential-dumping methods (e.g., targeting SAM registry hives or using tools like Mimikatz).
4. **Check for Lateral Movement.** Assess whether valid credentials were exposed or if the attacker moved horizontally across the network prior to the block.   
5. **Contain and Isolate.** If the attempt had succeeded, immediate device isolation and account containment would be enforced, alongside mandatory credential resets for compromised service or user accounts.    
6. **Preserve Evidence.** Export detection logs, EDR timelines, and relevant artifacts for forensic review.   
7. **Eradicate and Harden.** Ensure attack surface reduction (ASR) rules are active to block credential theft from LSASS, maintain strict PPL enforcement, and monitor continuous endpoint telemetry.
