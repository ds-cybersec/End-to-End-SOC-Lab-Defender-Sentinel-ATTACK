## Persistence (T1547.001)

Hands-on security investigation and multi-layer telemetry analysis of MITRE ATT&CK T1547.001 (Boot or Logon Autostart Execution: Registry Run Keys / Startup Folder). Traced attack execution across local Sysmon host logs (Event ID 1 and Event ID 13), Microsoft Sentinel SIEM (KQL) and Microsoft Defender XDR, and compared how Defender handled this technique against the earlier T1053.005 test.

---

## Test

Invoke-AtomicTest T1547.001 -TestNumbers 1

Output of the test:-

PathToAtomicsFolder = C:\AtomicRedTeam\atomics
 
Executing test: T1547.001-1 Reg Key Run
The operation completed successfully.
Exit code: 0
Done executing test: T1547.001-1 Reg Key Run  

## Structure

```text
My admin PowerShell console (PID 11916, opened 3:23:54 AM)
  └─ powershell.exe                  Invoke-AtomicTest T1547.001 -TestNumbers 1
       └─ cmd.exe (PID 13872)        5:43:45 AM
            │  cmd.exe /c REG ADD "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
            │             /V "Atomic Red Team" /t REG_SZ /F /D "C:\Path\AtomicRedTeam.exe"
            │
            └─ reg.exe (PID 12420)   5:43:45 AM
                 writes HKCU\...\Run\"Atomic Red Team" = C:\Path\AtomicRedTeam.exe

```
One command, one registry write. Unlike T1053.005 there is no second task and no SYSTEM component: the value lives in HKCU, so it only runs when this user logs on.

## Time Clarification: Local vs. UTC Timestamp Mapping

> **Timezone Reference Note:** Local host logs and Defender XDR record events in **Local Machine Time (IST / UTC+5:30)**, whereas Microsoft Sentinel indexes everything in **UTC**. For Sysmon output, the outer `TimeCreated` field represents local time, while the inner `UtcTime` field within the message body is recorded in UTC (e.g., *5:43:45 AM IST = 00:13:45 UTC*). 
> *Note on Audit Policy:* Unlike some techniques (such as T1053.005), this simulation required no changes to default Windows audit policies because Sysmon EID 13 is governed directly by the Sysmon configuration rule rather than native Windows auditing.

## Stage A: SYSMON FINDINGS - Sysmon logs in PowerShell

Command (targeted)

Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 500 |Where-Object {$_.Message -match "Run"} |Format-List TimeCreated, Id, Message  

Output: Mostly noise, with three relevant events at the top. The regex "Run" is too broad and also matched MpCmdRun.exe (Defender), dsregcmd.exe /RunSystemTests, tasklist.exe from the Azure Monitor troubleshooter, and dozens of vcruntime140.dll file-creation events (Event ID 11) from the Azure Connected Machine Agent. Only the newest three events belong to the test:  
•	Event ID 13 (Registry value set) at 5:43:45 AM: reg.exe wrote the value.  
•	Event ID 1 (Process Create) at 5:43:45 AM: reg.exe, PID 12420.   
•	Event ID 1 (Process Create) at 5:43:45 AM: cmd.exe, PID 13872.
