# Execution  (T1059.003)

Hands-on security investigation and multi-layer telemetry analysis of MITRE ATT&CK T1059.003 (Windows Command Shell). 
Traced attack execution across local Sysmon host logs, Microsoft Sentinel SIEM (KQL), and Microsoft Defender XDR, while troubleshooting log-routing and EDR licensing constraints.

By reading the Sysmon logs in event viewer/PowerShell , I can prove that this is MITRE ATT&CK T1059.003 (Command and Scripting Interpreter: Windows Command Shell) through several explicit fields:

<img width="1117" height="737" alt="sysmon" src="https://github.com/user-attachments/assets/8161ead3-ae12-4441-92d8-4ddb8f201d30" />

:-The Executable Image: The log explicitly shows Image as C:\Windows\System32\cmd.exe, which confirms that the Windows Command Shell interpreter was invoked.
:-The Command-Line Execution (/c flag): 
  The CommandLine field shows C:\Windows\system32\cmd.exe /c "C:\Users\ADMINI~1\AppData\Local\Temp\T1059.003_script.bat". 
  The /c switch tells cmd.exe to run the command string (the batch script) and then terminate, which is the classic behavior of a script interpreter executing commands.
:-The Process Lineage (Parent Process): The log proves how it was launched by displaying the ParentImage as powershell.exe and the ParentCommandLine running the Atomic Red Team framework script.
  This shows a script interpreter (PowerShell) spawning another command/scripting interpreter (CMD), matching the exact definition of technique T1059.003.

## ☁️ Stage B: Microsoft Sentinel & KQL Query Analysis

Clarification about the ingestion:-
Ingestion Check (SecurityEvent vs. Event)
Initially, querying the standard SecurityEvent table returned zero results. Further investigation revealed that the Azure Monitor Agent (AMA) was configured to send Windows Event Logs into the generic Event table.

<img width="1647" height="712" alt="sentinel query 1 " src="https://github.com/user-attachments/assets/222785fb-2311-4bef-8951-a38db03103d8" />

:-The Query (Event Table): The KQL code in the top pane searches the generic Event table (EventID == 4688) because your log-routing configuration (AMA/DCR) directed Windows security logs there instead of the default SecurityEvent table.
:-The Highlighted Match: In the results pane at the bottom, look closely at the highlighted yellow text in the RenderedDescription:
It shows powershell.exe launching cmd.exe with the exact command line: C:\WINDOWS\system32\cmd.exe /c ""C:\AtomicRedTeam\ExternalPayloads\T1059.003_script.bat""
:-The Timestamp: It matches your host logs and timeline down to the exact moment (9/20/2026, 9:58:10 PM UTC).

Why this view is important:
While your Sysmon logs (Event Viewer) proved what happened locally on the machine, this Microsoft Sentinel view proves that the event successfully ingested into your cloud SIEM, allowing a blue teamer to hunt for this technique across the cloud workspace
