## Why PowerShell Launching `cmd.exe` and Running `dir` Is Not a Red Flag

### 1. The Context Problem: "Admin vs. Attacker"
To an automated EDR tool, the exact same action can be either completely normal administrative work or a malicious attack depending entirely on who is running it and what the script contains:
* **The Normal Side:** System administrators, software installation scripts, and automated deployment tools constantly use PowerShell to call `cmd.exe` and run batch files (e.g., updating software, running internal company scripts, or installing patches).
* **The Attacker Side:** Attackers also use this method to drop a payload and run commands.

Because both admins and attackers use these native tools, security software looks for context clues (like malicious network connections, credential dumping, or injecting code into memory) rather than just the process name alone.

---

### 2. Harmless Content vs. Malicious Content
What did the batch file (`T1059.003_script.bat`) actually do under the hood? It mostly performed basic directory listings and file checks.
* If a batch file just looks around folders (`dir`), it looks like a standard script running housekeeping tasks. 
* If the batch file starts trying to disable antivirus, clear event logs, or reach out to a known malicious command-and-control server, then Defender instantly flags it. 

Because the behavior itself wasn't destructive, it didn't trigger an automated block.

---

### 3. Why Red Teaming Uses This Technique
The whole point of using a framework like Atomic Red Team is to test whether your defenses can catch "Living off the Land" techniques.
* Attackers love using built-in Windows tools (`powershell.exe`, `cmd.exe`, `wmic.exe`) precisely because they blend in with normal administrative traffic and often bypass basic security alerts.
* The fact that Defender didn't block the execution doesn't mean your lab failed—it actually proved a very important real-world lesson: EDRs alone can suffer from alert fatigue or blind spots on benign-looking native commands, which is exactly why Blue Teamers rely on SIEMs (like Microsoft Sentinel) and Sysmon logs to hunt for these behaviors manually.
