## Execution (T1059.001)  

Hands-on security investigation and multi-layer telemetry analysis of MITRE ATT&CK T1059.001 (PowerShell). Traced attack execution across local Sysmon host logs, Microsoft Sentinel SIEM (KQL), and Microsoft Defender XDR, capturing automated defense interception of credential-dumping scripts.

Test: Invoke-AtomicTest T1059.001 -TestNumbers 1  

Atomic test name: T1059.001-1 Mimikatz. It runs Invoke-Mimikatz -DumpCreds from the PowerSploit script Invoke-Mimikatz.ps1.

## Stage B: Microsoft Sentinel & KQL Query Analysis  

Clarification about the Ingestion (SecurityEvent vs. Event): Standard SecurityEvent log routing maps into the generic Event table depending on the Azure Monitor Agent (AMA) configuration.

The Query (Event Table): Searching the generic Event table (EventID == 4688) tracks process executions involving PowerShell script imports.  

### The KQL Query

Event
| where TimeGenerated > ago(2h)
| where RenderedDescription has_any ("Invoke-Mimikatz", "Invoke-AtomicTest")
| project TimeGenerated, Computer, EventID, Source, RenderedDescription
| order by TimeGenerated asc  

PowerShell script block events (Event ID 4104) or Sysmon process creation (Event ID 1) around 22:31 to 22:32 UTC showing Invoke-Mimikatz -DumpCreds.  

Correlation: The output matches the exact timestamp of the Atomic Red Team execution, proving successful end-to-end log forwarding from the local host to the Microsoft Sentinel cloud workspace.

## Stage F: Analysis  

Understand Analysis by looking through these 3 points.  
:-Response  
:-Why Benign Positive?  
:-Defender blocked this one but not T1059.003...WHY ?  

Response: no further containment action taken. Incident classified Benign Positive (authorized internal testing). Defender had already blocked and removed the payload, so isolate/kill/quarantine steps were not applicable.  

Why Benign Positive ?  
There are 2 words to be understood first: Benign and Positive.  

"Positive" (The Detection Side)  
Real signature match: Defender did not guess. Invoke-Mimikatz.ps1 is a well-known tool, and the alert named it exactly (Trojan:PowerShell/Mimikatz.A).  
Accurate detection: Mimikatz is used in real attacks to dump credentials from memory (LSASS). Defender correctly rated it High.  

"Benign" (The Intent & Context Side)  
Authorized testing: I ran Invoke-AtomicTest T1059.001 -TestNumbers 1 myself on my own lab machine, on purpose, to test detection.  
No harm done: the payload was removed before it ran, so no credentials were dumped.  

Because Defender correctly flagged a real offensive tool, but I was the one running it safely in my own lab, it is a Benign Positive.  

The Tool is RIGHT, but the Context is Safe = Benign Positive  

---  

## Why did Defender block this one, but not T1059.003?  

1.Content vs. behavior. In T1059.003 the batch file only ran dir and looked like harmless housekeeping, so there was nothing to signature-match. Here the script is a known malicious tool with a known signature, so it is caught by name and content, regardless of who runs it.  

2.Same technique, different payload. Both tests use built-in Windows shells, which attackers love because they blend in. What decides detection is what is inside the command: dir is invisible, Invoke-Mimikatz -DumpCreds is not.  

3.What this proves for a blue team. Defender gives strong protection against known tools, but a renamed, obfuscated or custom credential-dumping script may not match a signature. That is why the SIEM and Sysmon hunting from T1059.003 still matters.
